# 2.1.7 初次修复计划（2026-10-11，已被可用性修复取代）

当前实现和验收以 [可用性修复计划](PLAN-2.1.7-repair.md) 与 [验证记录](VALIDATION-2.1.7.md) 为准。下文保留初次排查历史，固定原行数、缺字拒绝和显式选字体的方案不再作为当前默认编辑流程。

## 根因

- `15b0dac9d0578d2802c4235a5ab881ed.pdf` 第 9 页实际为双栏。旧算法将同一栏沟中长短不同的空隙中心求平均，候选漂移到右栏文字附近（约 309.98pt），占用判定因此拒绝栏界，输出只有 column 0。真实空隙约 300.02–311.98pt，跨栏公式并不是这一页退化为单栏的直接原因。
- 页面文字编辑从 PDF.js 字体名称映射到系统字体，再用 Unicode 填入嵌入字体的浏览器字体。PDF.js 字体可能使用私有区 cmap；字体名正确也不能保证 Unicode 得到原字形。随后字号被四舍五入/钳制，行距量化到预设档，canvas 使用 top 基线和重新换行，最后以位图覆盖源文字。PDF 原生字体、定位、TJ 调整和文字状态没有写回。

## 实施

1. 栏沟聚类保留区间，以较窄半数空隙的左右端点中位数定位，避免短行/公式空隙拉偏；沿用既有人工校正和跨栏块流程。补齐三栏窄栏沟判定，并限制公式块向下扩展，防止吞入随后的普通正文。
2. 默认原位编辑直接解析并修改页面原有 Tj/TJ 文字指令。复用 pdf-lib 对象解析器和原字体资源；保留原有字号、字符间距、词间距、水平缩放、基线、变换、颜色，以及未改字形的定位。仅改变化字形的编码，逐字保留原 TJ 调整，在修改区间末端补偿长度差。草稿通过同一原生编辑逻辑和 PDF.js 渲染；明确选择字体后才使用既有格式替换路径。
3. 支持子集/复合字体、Unicode 多字节、连字、RTL、裁剪旋转和共享 Form 的隔离。无法可靠编码、需要自动重排或区域溢出时保留草稿并显示十语言错误，不静默替换字体、缩放或截字。写回失败回滚，保留撤销重做。
4. 新增本版本定向测试：真实第 9 页正反向框选、栏内隔离；构造稳定栏沟/跨栏公式；多语言原生指令、精确几何、共享内容隔离、保存重开、撤销重做及失败不修改。新增 Electron 验收覆盖实际编辑入口与错误后的草稿。
5. 页面组件按 PDF.js 加载任务的身份更新，避免修改后的文档复用同一 fingerprint 下的旧文字缓存。PDF.js 产生的同一行空格用于衔接文字片段；字号和实际行距保留精度，工具栏独立显示“原文字体”。复杂文字的一个 Unicode 对应多个上下文字形时拒绝猜测编码。
