# 2.1.12 修改计划

日期：2026-10-30（Asia/Shanghai）。采用 ponytail full，复用当前 PDF.js、pdf-lib 和测试目录，无新增项目依赖。用户要求先规划，随后修改、添加测试，仅运行本轮新增项，通过后打包。

## 样本归档与复现

两份原始输入按已有随机 32 位十六进制文件名规则复制到 tests/fixtures，原始字节不变，不保留原名映射，不移动/改写用户云盘原件。

- `39fb2a5696459c9b2d0e09f8334797c3.pdf`：五页 AcroForm，142 个字段；画布关闭全部注释外观，使填写值不可见。
- `5ce7046c487832eaf413c532c845d360.pdf`：十四页中文文档，包含无独立表注的有框表格；现有识别把整表当成单个图形，选区没有单元格约束。
- 新增文字使用 Canvas top 基线。已实测默认 Arial 16px 中文字形向画布上方伸出约 0.79px，重音字母约 1.94px，导致透明位图顶部切掉笔画。

## 修改范围与风险

1. 共用阅读渲染保留原生表单及未由软件覆盖层接管的注释外观。通过 PDF 原始引用 ID 精确排除已接管对象，避免高亮、文字、图片和水印重复绘制；不扁平化表单，不重写填写值。覆盖重绘、保存重开、撤销重做和页面缩放；检查导出/打印链路是否同样隐藏表单。
2. 在既有绘图证据中读取实际横竖框线，沿用矩阵、Form/路径裁剪和页边界保护。只认重复、闭合、含文字的网格，支持分段框线、合并单元格；不把背景矩形、单个框、坐标轴或普通正文栏当成表格。表格图索引使用真实网格边界，避免吸收邻近正文引用。
3. 文字映射标注单元格及边界。公共拖选/光标路径按起始单元格限制焦点、文字流和高亮矩形，保留格内多行及混合字体；右键、键盘延伸、反向拖选、跨页和精确引用调用一并检查。正文跨表选择保持既有整表隔离。
4. 添加/重编/缩放文字复用同一位图方法，改用实际字形升部确定基线并保留像素余量，避免中文、重音字母和下伸部裁切；保存外观与屏幕预览保持一致。保留原有标准 PDF 字体分支，避免无必要地栅格化英文。
5. 版本、锁文件、README、打包和测试说明同步 2.1.12。新建针对性单元和真实 Electron 验收，使用归档样本、生成的勾选/单选/多行/缺外观表单及合并单元格夹具；不运行旧测试全集。结果与截图放 tests/output/release-2.1.12，临时输入及环境放 tests/tmp/release-2.1.12；已有 gitignore 覆盖，无需增加依赖或忽略原始样本。
6. 执行新增项、typecheck、直接 electron-vite 生产构建、diff 和包内资源校验。macOS arm64 APP/DMG/ZIP，实际启动最终 APP 重跑新增窗口项；核对全部生产文件、版本、11 个 OCR 模型、图标、ad-hoc 签名、DMG/ZIP 和 SHA-256。没有 Developer ID 时明确未公证，不宣称 Windows 或历史全量验收。

## 复现后补充

打印拼版 embedPage 也会丢失原生表单外观：临时副本补齐缺失 AP 后，把可打印的正常外观（含勾选/单选当前状态和外观 Matrix）压入打印内容流，保留原文档。新生成外观是 PDFContentStream，不能只接受从磁盘读取的 PDFRawStream；测试包含此差异。单元格选区先确定纵向文字行，避免末行较短时被长行抢走焦点；空单元格不选择邻格。图中稀疏坐标网格不认作表格，带明确总图注的分图不被新单元格识别破坏。
