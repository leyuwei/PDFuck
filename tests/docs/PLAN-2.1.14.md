# 2.1.14 修改计划

目标：修复 PDF 文本选择、全文评价模板、搜索、书签导航/布局和文件合并流程；保持现有文档编辑、表格框选保护、导入转换及多语言行为。

## 修改范围

1. 检查文本选择的表格单元格约束和普通段落选择分支。修复普通单栏跨行/跨词框选漏字、相邻两行只能选中一行的问题；表格仍限制在当前单元格。使用用户给出的截图场景和已归档 PDF 回归样本确定根因，避免降低图表、双栏、公式及表格隔离。
2. 全文评价提示词增加持久化的“自定义”项。修改预置提示词文本后立即选中自定义并保存；切换语言、关闭重开窗口和重启后仍恢复自定义文本。显式选回预置项时保留其本地化提示词。
3. PDF 搜索打开时传入当前有效选区文本作为初始查询；Markdown/TXT 搜索沿用自身选区逻辑。初始查询只在新搜索窗口/新请求时应用，不覆盖用户正在编辑的查询。
4. 搜索增加“全词匹配”复选框，并把选项传入统一匹配逻辑；与正则、大小写、模糊匹配并用时明确禁用不兼容项。补齐十语言文案。
5. 书签点击使用目标书签的精确目的地完成导航，并避免页面滚动期间临近书签抢占活动高亮；保留页码、命名目的地和同页书签行为。
6. 调整书签树行布局，让页码始终贴近侧栏右边缘；删除按钮使用悬停覆盖/占位不改变页码位置，适配窄栏、长标题及 RTL。
7. 合并 PDF 入口在打开文件选择器前显示复用现有样式的模式弹窗，让用户选择插入当前文档或新建独立合并文档。选择新建时不覆盖现有文档/会话；取消和导入失败保持现有状态及错误处理。
8. macOS 双面打印使用系统打印后端的明确双面参数，避免 Chromium 静默打印只接受 UI 选项却被 CUPS 按单面派发；保留长边/短边语义，打印机不支持时沿用手动双面提示，并对参数构建和失败回退加回归覆盖。

## 多语言和测试

- 所有新增可见文字覆盖项目支持的十种界面语言，并通过既有目录审计规则。
- 双面打印测试覆盖 macOS 的 CUPS 参数、Windows 现有 DEVMODE 路径及单面回退，真实打印机硬件行为作为设备验收项单独记录。
- 新增 `tests/unit/renderer/src/lib/release-2.1.14.test.tsx` 覆盖文本范围/全词匹配、全文评价模板持久化/语言恢复、书签导航目标和合并模式状态。
- 新增 `tests/scripts/release-2.1.14-ui.cjs` 覆盖 PDF 选区和搜索预填/全词匹配、全文评价自定义项的修改与重开、密集书签跳转高亮和边缘页码布局，以及已有文档时的合并模式选择/新建后保留原会话。UI 检查覆盖十语言。
- 本轮仅运行新增测试项及必要的 `npm run typecheck`、直接 `electron-vite build` 和 `git diff --check`；不运行历史测试全集和一键发布脚本。
