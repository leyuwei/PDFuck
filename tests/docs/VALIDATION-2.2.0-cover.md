# 2.2.0 封面分栏误判验收

原件第一页的四行元数据在同一横向位置留出空隙。各行相隔约 37 PDF 点，约为该页典型字高的 2.6 倍。旧逻辑把这四行当成同一阅读带，给出距左边 221.28 PDF 点的分栏线。新版要求栏缝两侧有连续的正文行。行距较大的版式仍可凭多行宽正文建立分栏证据。手动边界继续优先于自动推断。

## 新增用例

- 15 项单元测试覆盖十种语言的封面字段、长字段表、字段复制顺序、手动覆盖、短双栏、窄栏和大行距。
- 源码窗口检查 15 个页面。原件和脱密副本的前三页均无自动边界，正文页保留正确双栏。另通过 6 次缩放检查、3 次添加边界并恢复自动、2 次正反向字段拖选及复制。
- 四页合成 PDF 位于 `tests/fixtures/cover-columns-220.pdf`，包含封面、短窄双栏、宽行距双栏和长字段表。用 `tests/scripts/release-2.2.0-cover-ui.cjs --generate` 可以重建。

## 2.2.0 回归

执行 7 组单元测试共 107 项，以及 11 组既有源码窗口专项。覆盖字形、图表、自动分栏、页眉页脚、比例输入、打印预览、工具栏、图题、缩放宽度、导航和批注基础场景。另执行 108 项页眉页脚 PDF 矩阵和 42 项紧邻图表 PDF 矩阵。

缩放宽度旧测试仍要求已确认的百分数显示两位小数。本轮更新为分别核对输入草稿与确认值，保留 96 项宽度验证。用于缺字检查的初始原件已不在给定路径，十种语言、原有合成字形和脱密 PDF 的像素检查已重跑。图表和封面专项使用可读取的原件和脱密副本。

TypeScript 检查、生产构建与 diff 检查通过。README 摘要和本轮受检原件摘要一致。macOS arm64 成品保持 2.2.0，采用临时签名。通过签名、文件内容及哈希静态校验，成品未启动。
