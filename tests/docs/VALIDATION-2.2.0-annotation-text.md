# 2.2.0 批注互操作与综合审稿验收

## 批注读写

原件第 2 页的目标高亮批注在 `/Contents` 中已有完整的 UTF-16BE 文字。批注已去除 emoji，旧写入路径仍生成了无格式的 UTF-16BE `/RC`。PDF.js 读取旧字段时出现 XHTML 解析错误。将同样的混合文本编码为带 Unicode 字符引用的 ASCII XHTML 后，独立解析器能还原文字、空行和加粗样式。规范约束见 [PDF 32000-1 第 12.7.3.4 节](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf)。

无格式批注只输出标准纯文本。带格式的批注同时保留标准纯文本及规范的 XHTML。保存、另存和 PDF 导出会迁移旧 PDFuck 字段。原纯文本、批注信息和第三方富文本保留。直接保存无编辑的旧文档、取消另存和另存副本均通过源码窗口验收。

PDF.js、MuPDF 和 macOS PDFKit 核对修复后的原件临时副本、脱密副本和 3 条合成备注。覆盖中文、混合语言、换行、标点、emoji、去除 emoji 后的编辑和富文本。独立读取器核对的是文件字段及解码结果。

## 综合审稿

综合预置模板覆盖十种界面语言。末尾只给出一档建议，要求按稿件贡献、证据和修订范围说明理由，使用公允且符合期刊常规的审稿尺度。全文审稿识别文档主要语言，选区润色使用选中的文字，批注建议优先用手动记录的上下文，自动批注使用所在页。扫描件或语言不明确时，提示模型依据材料识别回复语言。文件发送模式只附 PDF 和提示词。翻译保留用户选择的目标语言。

用模拟接口检查 OpenAI 兼容和 Claude 请求结构、十种语言和少量外语引用、旧固定语言后缀、扫描件回退、自动批注及翻译。源码窗口检查从旧默认模板恢复，以及中文界面下分别发送英文文档的文本和文件。两次请求均要求英文回答，并生成预置的模拟评审回复。实际外部 API 请求为零。

- 脱密 PDF 共 13 页，正文及批注文字均为合成内容。目标位置的批注保留旧编码以复现问题。比对 964 条较长原文，归档清单位于 `tests/fixtures/sanitization-manifest.json`。
