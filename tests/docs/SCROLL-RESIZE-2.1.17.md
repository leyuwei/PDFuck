# 滚动提示与侧栏拖动修复验收

本轮保留 2.1.17 版本，根目录 README 不作修改。不运行历史全量测试，不启动成品复测。

## 修复内容和根因

1. 删除纸张背后的大页码：移除全部装饰 DOM、CSS、额外层级与 `--viewer-inline-size` 的 ResizeObserver 写入，恢复原本的纸张容器。保留快速滚动时的纯数字浮窗。
2. 缩放不触发浮窗：滚动提示只接受明确的垂直滚轮、滚动键或原生滚动条输入；Ctrl/Meta 滚轮立即清除判定。每次缩放值改变也清除采样、输入意图和显示状态，排除按钮缩放、适宽、适页与锚点恢复产生的位移。
3. 提高阈值：原 96 px 累积规则改为同方向 220 ms 滑动窗口，至少两个实际滚动样本、移动不少于 `max(420 px, 阅读区高度 × 65%)`，且速度至少 1.8 px/ms。方向反转清空累计；慢速移动不会无限积累，小幅后续滚动不延长提示寿命。拖动滚动条属于明确定位操作，仍允许低速触发。浮窗继续只显示数字，沿用主题色、顶部提示栈和停止后淡出。
4. 两个侧栏原有 200 ms 宽度动画造成持续追赶鼠标；逐次 React 更新还会重绘列表并触发 PDF 自动适配。现共用 `useSidebarResize`：拖动期间关闭尺寸动画，每帧最多直接更新一次 DOM 宽度，松手才提交 React 状态；PDF 自动适配与阅读位置追踪在拖动期间暂停，结束时执行一次必要的适配。保留原宽度边界，处理丢失捕获、取消、失焦和卸载清理。手柄改为逻辑边缘，RTL 下按实际方向伸缩。
5. 外层网格默认的内容最小宽度还会撑大整个工作区。在 1720 px RTL 源码窗口中，修复前测得网格轨道为 1731 px，且侧栏继续加宽会进一步把界面挤出窗口。外层改为 `minmax(0, 1fr)`，工作区允许收缩，使阅读区能报告真实宽度并在结束拖动后正确适配。

没有新增依赖或固定语言文案；两个侧栏继续使用已有十语言标签。文字样式偏好、批注状态浮层、多栏框选等此前功能代码未回滚。

- 21 项新单元/组件通过：小幅/孤立滚动、窗口高度阈值、慢速/方向反转、无用户输入的位移、Ctrl/Meta 缩放、按钮缩放时清空意图、文档切换、拖动滚动条、拖动期间的排除；两个方向、LTR/RTL、每帧合并与拖动期间无组件重绘、宽度限制、错误指针、取消、失焦和卸载清理；背景层删除。
- 源码窗口专项通过：合成 32 页 PDF、300 个书签和 160 条批注；轻微滚轮、多次小幅滚轮、持续慢速滚动均不显示；明确快速滚动、原生滚动条可显示并正常淡出；按钮、适宽/适页和 Ctrl 滚轮没有任何浮窗闪现。浮窗仍与临时目录提醒分开。
- 40 次真实侧栏拖动通过：十语言 × 两主题 × 两种侧栏，每次实际改变宽度，包含 RTL 下书签收缩。每次检测 8 个渲染帧，目标宽度误差均为 0 CSS px；拖动期间纸张显示宽度和缩放值不变，松开后每次最多一次适配（40 次中共 2 次需要适配）。同时确认两个侧栏和工作区没有挤出窗口。这里测的是渲染帧内的边界位置，不能换算为所有设备上的端到端输入延迟或 FPS。
- 新单元与源码窗口是本轮唯一执行的测试入口。旧 96 px 触发单元已标为历史规则，由新增严格阈值测试替代；此前背景大页码的 UI 脚本属于历史交付记录，不作为当前入口。
- 类型检查、直接生产构建和补丁空白检查通过。

结果：`tests/output/release-2.1.17/scroll-resize-unit.json`、`scroll-resize-ui.json`；源码截图：`scroll-resize-source/`。所有新 PDF、书签、批注和截图均为固定合成内容，临时文件与隔离用户配置在 `tests/tmp/release-2.1.17/scroll-resize/`。没有读取或另存本轮用户原件，没有改变既有脱敏档案。
