# 2.0.32 验证记录

日期：2026-09-09，Windows x64。状态：434 项单元测试、65 项 Windows 发布检查及成品完整性核验全部通过；已生成安装版与便携版。

## 改动与使用

- OCR 继续离线执行。选择更适合实测样例的已锁定模型（日文保留 `4.0.0_best_int`，其余使用 `4.0.0`），300 DPI 输入自动纠斜，低置信度最多再识别一次；短文本改用稀疏分割，长文本尝试 Sauvola 阈值。复识别只有置信度提高且字符保留率足够时才替换结果。单页工作线程时限由 180 秒增加为 300 秒。
- 中文、日文连续字符间的伪空格在保存的 OCR 文字流、框选复制和 AI 正文提取路径统一整理；保留其他语言的词间空格。纠斜的文字层转换回原页坐标，不修改页面像素。修复 Tesseract 阿拉伯语反射文字矩阵与 PDF 阅读器双向处理造成的倒序，同时修复 RTL 拖选、字符边界与高亮宽度。
- “批注 → 实验室 → 模型设置”升级为配置列表与参数表单。支持多个命名配置，编辑/保存与激活分离，旧单模型设置自动迁移；自定义地址、模型、密钥和预算保留，旧默认 120 秒/16,384 Token 迁移为新的默认预算。顶端明确显示当前激活模型；取消不保存，重启保持选择，切换默认服务商不携带旧服务商密钥。
- 新增 Grok。支持 OpenAI、Claude、BigModel、Doubao、DeepSeek、KIMI、自定义兼容接口；表单包括连接、总输出、超时、温度、Top P、Thinking 模式/强度、Claude 思考预算、惩罚、Seed、高级 JSON。JSON 不能覆盖原文、模型、流式控制、工具调用或总预算等受管理字段。
- 默认单次请求 600 秒、65,536 Token；可配置到 3,600 秒和 262,144 Token，实际受服务商模型上限约束。恢复总时限为配置超时两倍，最高 7,200 秒，每组请求最多尝试 24 次。首包与思考间隔不再被旧的短看门狗提前取消。
- 根据服务商发送 Thinking 参数；遇到明确参数不兼容，可切换 Claude adaptive/manual、移除拒绝的参数或降低思考强度。截断先扩容、按服务商上限协商，再按允许的 Thinking 降级/分批恢复；取消和鉴权失败停止。允许用户关闭 Thinking 降级，不把截断文本或 HTTP 200 错误流当成成功结果。
- SSE 增量解析每个事件，兼容分片、多行 data 与 Unicode；长思考显示最近部分，完整最终回答仍保留。仅显示服务商返回的思考，不生成虚假推理过程。

## OCR 实测结果与边界

固定系统字体渲染的 11 个短句，经真实引擎与保存后的 PDF.js 提取计算字符错误率（CER，去空白、NFC、区分大小写）。这只是回归样本，不能代表任意扫描件的平均准确率。

| 主要语言 | 错误字符 / 原文字符 | CER |
| --- | ---: | ---: |
| 英语 | 0 / 37 | 0% |
| 简体中文 | 0 / 13 | 0% |
| 繁体中文 | 1 / 13 | 7.69% |
| 日语 | 0 / 15 | 0% |
| 俄语 | 8 / 34 | 23.53% |
| 西班牙语 | 0 / 37 | 0% |
| 法语 | 0 / 37 | 0% |
| 德语 | 0 / 38 | 0% |
| 葡萄牙语 | 0 / 35 | 0% |
| 韩语 | 0 / 14 | 0% |
| 阿拉伯语 | 0 / 29 | 0% |

繁体中文样例将“製”识为“裹”；俄文将 `исходный` 识为 `ИСХОДНЫЙ`，旧模型也存在同一大小写误判；测试对该已知案例设置 25% 上限，其余主语言短句上限 10%，原始错误完整记录。韩文主句的字符正确但仍有引擎插入的词内空格；其混排英文页脚 `PDF OCR 2026` 识为 `2 008 2026`。页脚单独记录，不纳入主语言短句 CER。旋转裁剪英文页中仍有 `Keep → Kesp` 错字。

同一中英多行样例的模型对比：旧 `4.0.0_best_int` 置信度 89，将“之后”识为“忆后”；新 `4.0.0` 置信度 95，该样例原文正确。置信度是引擎指标，不等于准确率。日文对比发现完整模型把混排数字识为带圈数字，因此保留原日文整数模型。

未使用生成式 AI 自动改写 OCR 原文，避免把人名、术语、公式和数据猜成另一段文字。低清、手写、复杂表格/公式、混合脚本和特殊字体仍需校对；其他 PDF 阅读器可能根据自身几何规则再插入空格，本软件的复制路径会统一整理 CJK 空格。
