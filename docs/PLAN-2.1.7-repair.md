# 2.1.7 可用性修复计划（2026-10-12）

上次交付把字形区间不增长当成原位编辑的必要条件，错误地拒绝了普通增字、换行和格式调整。仅验证缩短替换，未验证普通用户编辑。栏线的界面位置另有一次从文字极值推断的算法，未复用栏沟；窗口还使用系统替代字体度量，短行空隙中心聚类会把同一栏沟拆开，公式碎片因此仍能拉偏识别。

1. 栏界只计算一次，选择、段落宽度与界面栏线复用同一结果；实际窗口验证 testOct 第 9 页栏线位于真实栏沟，并覆盖正反向选择及缩放。
2. 原字形能够直接复用的小改动保留精确写回；普通增字、换行及格式变化自动进入段落排版，不再要求用户改字体或缩短至旧字符宽度。通过已有 Chromium PDF 输出生成矢量文字，按原基线、字体、字号、色彩和栏内宽度排版；剔除原文字而不覆盖背景、图片和线条。复用嵌入字体的真实字体程序与字符映射，缺字由系统字体自动补齐。
3. 预览与最终写回共用输出。支持再次编辑、撤销重做、保存重开；仅真实无法定位或操作失败时保留草稿并报错。排版可以增长行数，界面预览与输入区域随之更新。
4. 只运行关键定向回归：真实英文/中文文档普通增字与格式修改、矢量与可复制文字、段落外像素隔离、保存重开与撤销重做；实际栏线坐标和左右栏隔离。成功后重新生成 2.1.7 macOS arm64 APP / DMG / ZIP，实际运行成品再验收并更新 SHA-256。

实际窗口排查补充：连续写回的内存 PDFContentStream 与预览读取的保存 PDFRawStream 不一致；编辑前重新加载同一保存快照。标题、公式编号与正文曾因相近字号和宽松垂直间隔合并，改为独立段落以保留首行缩进和基线。Chromium 对共用字形的 CJK 部首、阿拉伯字形可能选错 ToUnicode 别名，修正请求对应的 Unicode，删除输出中冗余逐字 ActualText 包装以保留连贯词语提取。
