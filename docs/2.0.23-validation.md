# 2.0.23 修复与验证记录

日期：2026-09-07。基于 main 的 4c372c2 和当前工作区的 2.0.22 修改继续修复；本轮未提交或推送。

## 定位与修复

| 问题 | 复现与根因 | 修复结果 |
| --- | --- | --- |
| AI 建议文字竖排 | 旧按钮使用 22px / 1fr / auto 三列，改为纯文字后文字仍落在第一窄列；真实窗口中显示为 7 行 | 删除旧三列子元素样式，改为普通横向按钮；同窗口变为 1 行 |
| 拖动与软件标题栏冲突 | 原弹窗允许拖至应用标题栏区域，初始顶部为 20px，应用标题区底部为 98px | 复用已有浮窗定位与拖动函数，保持至少 8px 间距；弹窗及背景设置 no-drag，拖动不再挪动原生窗口，缩小软件窗口后弹窗仍避让标题栏 |
| 缺少直接关闭入口 | 标题只有文字和拖动图标 | 增加右上角关闭按钮，名称与提示使用现有多语言文案 |
| 某些条目双击失败 | 首次选中会自动滚动，部分可见条目上移约 87.33px；另外，富文本每次重绘重设 innerHTML，删除第一次点击的文字节点，使第二次点击失去双击目标；回复和说明没有双击入口 | 指针选中保持位置，外部定位仍可滚动；相同富文本 HTML 保持属性对象及文字节点稳定；正文、回复、说明和作者内容区共用双击入口，支持 Enter/空格键 |
| 点击背景不能关闭 | 背景没有取消处理 | 背景点击、右上角关闭和 Escape 共用取消逻辑；不提交未确认的草稿。点击弹窗内部不会关闭，从内部拖到背景也不会误关闭 |
