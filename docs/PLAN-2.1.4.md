# 2.1.4 搜索升级计划

2026-10-06。先检查 README、PACKAGING_GUIDE、字号 VI 与搜索/快捷键调用链，再编码。

根因：PDF 搜索在 Markdown DOM 内，受到 `.md-workspace input` 的 100% 宽度和 padding 污染，复选框挤压裸文字；固定 440px 外框也不随字号增长。Ctrl+F 的全局处理排除了 textarea，源码没有搜索入口。

方案：

- 提取现有 PDF 搜索窗，源码和 PDF 复用同一组件及匹配函数，不增加依赖。通过 portal 放在 app-shell 内，与 Markdown 工作区平级，隔离表单样式并继承应用主题/强调色/字号/RTL。
- 外框宽度随正文字号增长并受视区限制；标题固定、正文滚动，复用浮窗拖动/避让。输入与搜索按钮允许整组换行，选项采用不压缩的 checkbox 和完整文字块，长译文自然换行。使用三档字号变量、逻辑方向及主题强调色。
- 源码 Ctrl/⌘+F 打开源码搜索；PDF 区域继续搜索生成的 PDF。工具面板入口按当前区域路由；仅源码视图也能使用。两窗互斥，重复快捷键聚焦已有输入，Escape/关闭返回原焦点。
- 复用大小写、忽略空白的模糊匹配、正则和预设；源码结果显示行号并精确选中原始范围、滚动到匹配处。保留 PDF 页码/高亮。最多展示 200 条，多余明确标记；空/错误状态可访问。输入法 Enter 不触发搜索。
- 内容变化取消过期搜索、清空旧结果；切换文档使用独立实例。源码搜索不改内容或历史，不依赖 PDF 刷新。
