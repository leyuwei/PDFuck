| 问题 | 原因 | 修改与验收 |

| 右键菜单越界、被遮盖 | 绝对定位基于页面坐标，未测量尺寸；层级受页面父节点限制 | 视口坐标、测量后换向和夹紧，原生 popover top layer；16 种角落场景及覆盖命中检查 |

1. 类型检查、全部单元测试、十种语言词条审计。

## EPS 转换依据

Ghostscript eps2write 会对本例透明页面整体栅格化，回读得到 0 个文字对象、0 个路径；因此未采用这一方案。Cairo 后端把不支持的透明操作限制在局部矩形，文字与常规绘图操作输出为矢量：[Cairo PostScript 文档](https://www.cairographics.org/documentation/using_the_postscript_surface/)。本例实际保留全部 147 个非空白文字字符和 86 个路径操作。原有位图素材及必要的透明度局部处理仍为图像，EPS 不能承诺完整 PDF 的透明矢量语义。

目标电脑需要 Poppler (`pdftocairo`)。测试回读另使用 Ghostscript，视觉检查使用 `pdftoppm`。macOS 本轮使用 ad-hoc 签名，不等于 Developer ID 公证。Windows 原生安装与打印验证须在 Windows 执行。

## 回归中追加修复

- macOS 1080 像素窗口的顶部工具按钮占用过宽，长文件名视口被挤到零宽。缩小现有响应式布局中的按钮和间距，保持工具区居中；发布测试要求标题视口至少 24 像素并核对品牌、工具区安全间距。测试等待按钮尺寸过渡完成后读取几何。
- 页面管理输入测试改用两个真实原生窗口切换验证焦点。macOS 上直接 `BrowserWindow.blur()` 并未产生正常的窗口失焦事件，却会重置 Chromium 首响应者；中文组合输入、真实键入、DPI 草稿和焦点断言均保留。测试失败时销毁测试窗口，避免退出卡住。
- 打印回归按平台验证打印机首选项：Windows 保留驱动设置断言，macOS 验证不显示 Windows 专属入口；保留十语言、质量、份数和双面作业检查。
- 发布脚本不再把 Gatekeeper 全局关闭时返回的“通过”记录为正常安全评估。本机无 Developer ID，交付应用使用 ad-hoc 签名，未经 Apple 公证。
